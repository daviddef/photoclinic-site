Why the size and file count do not match after copying iCloud Drive

You copied a big iCloud Drive folder to an external drive and the two folders show different sizes and different numbers of files. Some of that is normal. Some of it means files are missing. Here is how to tell which.

Download for Mac

Last reviewed 26 October 2026. Written by the Photo Clinic team from what we learned moving large photo libraries. See how we write these guides.

1. Files that are only in iCloud

With Optimise Mac Storage on, many iCloud Drive files are not on your Mac at all. They show a cloud icon, and the Mac only holds a small placeholder. Finder shows the full size of such a file, but it takes almost no space on disk. To copy it, macOS first has to download it. If the download is slow, you are offline, or the file is huge, Finder may stop, show an error, or skip it. This is the most common reason a copy comes out short.

Check: in Finder, a small cloud icon with a down arrow beside a name means the file is not downloaded.

2. Size and “size on disk” are different numbers

Get Info shows two sizes. Size is how many bytes the files contain. Size on disk is how much space they occupy, rounded up to the drive's allocation unit. Many small files take more space on a drive with a big allocation unit (exFAT drives can use units far larger than a Mac's own drive), so a folder can look larger on the copy while holding the same files. Compare Size, not Size on disk.

3. Hidden files change the count

  • .DS_Store files hold Finder's view settings for each folder. They are created and removed freely.
  • ._name files (called AppleDouble files) appear when you copy to a drive that is not formatted for Macs, such as FAT or exFAT. They hold extra Mac information for the file next to them. They add to the file count and are not a sign of a problem.
  • Finder's item counts leave hidden files out, but Terminal's counts include them. Counting in two different ways produces two different numbers.

4. Packages are one item that holds many files

A .pages or .numbers document, a .photoslibrary, or an app, looks like one file in Finder but is really a folder full of files. A tool that counts one will not match a tool that counts the other.

5. Names the destination cannot hold

Some file systems refuse certain characters, very long names, or treat accented letters differently from the Mac. A file with a name the destination cannot store can fail to copy, or arrive under a slightly different name. If you see “file not found” for a name that looks fine, this is a likely reason.

6. Files that changed or moved during the copy

iCloud Drive keeps syncing while you copy. A file you moved or deleted after the copy began cannot be found any more, which produces a “file not found” message. Those are harmless, but they add up when you move many files.

How to find exactly what is missing

Do not compare folder sizes. Compare lists of files. Two ways:

  1. In Terminal. Count real files on each side, leaving out the .DS_Store noise: find "SOURCE" -type f ! -name ".DS_Store" | wc -l and the same for the copy. To list the differences, compare the relative paths of both sides with diff. On older versions of macOS, files that are not downloaded appear in Terminal as small .name.icloud placeholder files.
  2. With Photo Clinic. Open Copy from the cloud, tick the same folders, and press Compare with what is already copied. It looks at your existing copy wherever it is, and shows how many files are already there with the right size, which are missing, which are cut short, and which exist only in the copy, folder by folder. Then Copy the gaps copies only those files.
A file with the same name and a smaller size is a cut-short copy. Compare sizes as well as names: a copy that stopped part-way leaves a file that exists but is not complete.
